# SoundCoding

**コードのつながりを、耳からも。** 仲間のコードを読み、関数の声が接点で呼応する様子を聴く、小規模な JavaScript 向けのレビュー試作です。違う書き方に優劣を付けず、気になった関係を二者のコードで確かめます。

[公開デモ](https://soundcoding-ensemble.kouduki.chatgpt.site/) · [変換ルールとAPI](docs/MAPPING.md) · [3分デモ](docs/DEMO.md) · [設計レビュー・実装検証の記録](docs/REVIEW.md)

## はじめる

Node.js と Python 3 を使い、このディレクトリで実行します。

```sh
node scripts/build.mjs
python -m http.server 8768 --directory dist
```

`http://localhost:8768` を開き、「前 → 後を聴く」を押します。最初のサンプルでは、同じ呼出し箇所を変更前から変更後へ続けて試聴できます。ソース変更後はビルドを再実行してください。

呼ぶ側のコードと、相手の抜粋を表示し、演奏の根拠となるブロック・呼出し・返却・利用箇所を強調します。停止するとその接点を保ったまま読めます。コードを手でスクロールすると自動追従を解除します。声のボタンは関数の単独試聴、接点のボタンは二者のやり取りの試聴です。

## 5つのサンプル

| サンプル | 見る変更 | 音や記録の位置付け |
| --- | --- | --- |
| 01 依頼は、どちらの相手へ | `prepareDelivery` の呼出先を `planStandard` から `planExpress` へ変更。両相手の定義は同じまま。 | 引用する相手の主題が変わる。両版とも意図した配送計画で、不具合の正解例ではない。 |
| 02 同じ仕事、違う節回し | 集計の `reduce` を `for…of` に変更。 | 変更ブロックの奏法を聴く。55組の配列と明示例で同じ結果を確認したが、全入力の同値性証明ではない。 |
| 03 見つかったことと、状態は別 | `object/null` の正常な存在確認。変更はコメントと整形だけ。 | 同じ音を保つ。オフラインのプロフィールも、見つかったオブジェクトとして表示する。 |
| 04 返す値と、受け取る側 | 予約サンプルの `base → draft`。返却する値と集計の書き方が変わる。 | 値の形や意図をコードで確認する。保存済みのテスト記録は11/11から9/11へ変わる。 |
| 05 レビュー後の受け取り方 | 予約サンプルの `draft → aligned`。`if (!reservation)` を `if (!reservation.ok)` へ変更。 | 接点の主題は同じ相手のまま。保存記録は11/11だが、「正解の和音」に変える方式ではない。 |

人物とレビュー依頼は創作です。作者や人格・技量を音から推定しません。持ち込みコードには架空の担当者を割り当てません。

## 手元のコードを使う

「コードを開く」は新しい入力、「変更後を開く」は直前の版と比較する修正版の一式です。修正版はファイル全体を置き換えるので、残すファイルも含めて選びます。新しい入力を無関係なサンプルと比較しません。画面上の「編集して聴く」でも、表示中のファイルを変更して直前の版と比較できます。

複数の `.js` / `.mjs` / `.cjs` ファイル、または「コードを書き出す」で保存した変更セットJSONを読み込めます。フォルダー構造や同名ファイルを保持する場合は、相対パスを含むJSONを使います。現在のファイル選択はフォルダーの一括読込ではありません。

```json
{
  "format": "soundcoding-source/1",
  "files": {
    "src/main.js": "import { value } from './value.js';\nexport function run() { return value(); }",
    "src/value.js": "export function value() { return 1; }"
  }
}
```

**入力コードはブラウザ内で静的解析し、実行・外部送信しません。** 上限は24ファイル、合計300,000文字、1ファイル150,000文字です。対応の中心は JavaScript ES modules の名前を持つ関数と解決可能な静的呼出しです。TypeScript / JSX、CommonJSの依存解決、任意の動的呼出し、外部ライブラリ内部、全実行経路の解析には対応していません。`.cjs` の選択が可能でも、`require` の関係を解決できるという意味ではありません。

「ここをメモ」は接点・版のハッシュとメモをこのブラウザに保存し、Markdownへ書き出せます。ソース本文を自動で永続保存する機能ではありません。

## コードから音になる仕組み

- Acorn の AST から関数、関数本体の文単位ブロック、静的に解決した呼出しと根拠のソース範囲を取り出します。
- 関数の識別子から主題と基本音色を固定し、ブロックの反復・集約・分岐・`await` を節回しへ対応させます。構文から推定した業務役割で音色を変える方式ではありません。
- 接点では、呼ぶ側が相手の4音を引用し、相手が自分の音色で応答し、呼ぶ側が同じ主題を受け取ります。最後はその二者だけを重ねます。
- 比較では対応するブロックと接点の枠を揃えます。空白・コメント・読込順で既存の声を変えず、無関係な追加で全曲のテンポを圧縮しません。移動・改名は一意に対応できる場合だけ同一性を引き継ぎます。

これは静的な構造の演奏です。時刻は実行時間ではなく、同時に鳴る声は実処理の並行実行を意味しません。すべての変更が音に現れるわけでもありません。特に `.ok` の参照へ直しただけで、接点を「不協和から正解の和音」に変えることはありません。音の好みとコードの正しさは別です。

## 根拠と検証

「コードの楽評」は、コードの書き方、相手との関係やその変化、レビューで確かめたい問いを読む欄です。例えば、一文で相手へ委ねる関数、更新を一つの式にまとめる `reduce`、更新を行として見せる反復を、実際の記述から批評します。「この読み取りの根拠」でコードの抜粋と該当箇所へ戻れます。

楽評はAST・接点・比較結果から規則で組み立て、サンプル名ごとの文章へ切り替える方式ではありません。リフ、レガート、小品などはコード作風の比喩で、楽曲ジャンルの判定や品質点ではありません。受取条件の差など、現在の音では表現していない点は楽評にも明記します。

「この接点の根拠を見る」は、呼出し・返却原文・限定した `if` の利用箇所をまとめます。**楽評も根拠表示もブラウザ内のローカル処理であり、AIによる追加調査やテスト実行ではありません。**

```sh
node --test tests/*.test.cjs
node fixtures/verify.mjs
```

前者は解析・楽譜・fixtureの自動テストです。後者は同梱する予約コードをNode.jsで実行し、`draft` の意図した2件の失敗も再現する検証器です。最新の統合結果は [検証記録](docs/REVIEW.md) で管理します。

画面の「テストの記録」は、ソースのSHA-256が一致する予約サンプルの保存記録だけを表示します。最初の3シーンには、Nodeでのfixture検証はありますが、画面に照合する実行記録はまだ収録していません。これらや持ち込みコードを、ブラウザで実行済みとは表示しません。

予約の `draft` は、拒否を表すオブジェクト自体を真偽判定し、期待した `sold-out` に対して `confirmed`、期待0回に対して料金計算1回となります。在庫は減らず、例外でクラッシュする例でもありません。明示的に選ぶテスト失敗の中断は、この記録を表す演出であって実行時刻の再現ではありません。
