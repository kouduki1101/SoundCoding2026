# Checkout Lab

実際に動く、小さなオンラインショップのローカルデモです。実決済・メール・個人情報は使いません。

リポジトリからはルートで `pnpm install --frozen-lockfile`、`pnpm sample:checkout` を実行し、http://127.0.0.1:4174 を開きます。
ダウンロードしたZIPでは、このフォルダで `npm ci`、`npm start` を実行します。Node.js 22以上が必要です。

## 試すこと

1. Field Notesを2冊にすると、通常商品$48に20%引きが適用され、上限$8で止まります。
2. Gift Cardを追加しても割引対象とポイント対象には入りません。送料は$3です。
3. OLDクーポンは期限切れ。会員を外すとポイントを付けません。
4. 注文を確定するとサーバーが価格・期限を確認して保存します。再読み込み・サーバー再起動後も履歴を表示します。
5. ページ読み込み後に接続を切っても見積もりを変更できます。注文の確定には接続が必要です。

クライアントが送るのは商品ID・数量・会員区分・クーポンIDだけです。価格・割引率・現在時刻はサーバーが決めます。同じ注文IDでの再送は重複注文を作りません。
`.local/orders.json` に最大200件保存します。リセットはサーバーを止めてこのファイルを削除します。
このサーバーは127.0.0.1だけで待ち受けます。認証・決済・在庫管理を持たないローカル実演用です。

## Code Grooveとの対応

Code Grooveの「保存済み実解析」は、`fixtures/repos/checkout-flow/src` の13関数とREADMEを調べた本物のGemini記録です。
アプリの画面・サーバーは同じ決済コードを実際に呼び出します。Git内ではrunnerが共通ソースを直接bundleし、ZIPではそのソースを一字も変えず`src/`へ同梱します。
`preview.ts`はブラウザ内の見積もり、`pricing.ts`と`rewards.ts`はサーバー確定時の計算、`checkout.ts`は保存とレシートです。
画面・起動用サーバーは記録後に追加したため、保存済み解析の対象外です。未検査の画面まで健康と表示しません。対象READMEは`ANALYZED_README.md`に同梱します。

正常動作していても、将来キャンペーンを追加すると複数経路の考え方を揃える必要があります。一方、オフライン見積もりとサーバーの確定処理には分けておく理由があります。
デモはこの設計上の判断を聴いて調べるもので、壊れた機能や最初からある改善後バージョンとの比較ではありません。
