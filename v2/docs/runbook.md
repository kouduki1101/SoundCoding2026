# 運用手順

## 配備

mainへマージすると、GitHub Actionsの「CI and deploy」がテストと秘密情報検査を実行します。両方が成功した場合、Cloud Buildでイメージを作り、Cloud Runのwebと非公開workerを更新します。配備後はイメージ・revision・トラフィック、ヘルスチェック、公開サンプル、APIのアクセス制御を確認します。詳細は[CI/CD](CI_CD.md)を参照してください。

配備したイメージとrevisionは非公開の運用記録に保存します。障害時は、その記録から直前の動作確認済みイメージへ戻します。

## アクセス制御

私有プロジェクトは所有者だけが閲覧できます。Cloud Storageを非公開にし、workerはCloud TasksのOIDC認証で呼び出します。認証情報はSecret Managerなどの非公開の管理先で扱います。

## 解析の停止

実解析を止める場合はruntime controlのkill switchまたは`ENABLE_LIVE_ANALYSIS`を使います。保存済みの結果は引き続き再生できます。実解析が失敗した場合は、その失敗を表示します。

Cloud Tasksの実行状態とジョブのlease・retryを照合し、同じ要求を重複して投入しないようにします。

## 保存と費用

私有コピーのアクセス期限は7日です。削除要求後は閲覧を拒否し、保存物を削除します。公開デモの固定データは私有コピーと別に管理します。

東京リージョン、Cloud Runの最小インスタンス0、webの最大2、workerの最大1、Cloud Tasksの同時実行1を維持します。予算アラートと実請求を確認し、AIの予約・消費トークンと利用枠を監視します。
