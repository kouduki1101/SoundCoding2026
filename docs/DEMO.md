# 3分デモ：同じ声が、違う相手と仕事をする

現行ローカル試作の実演案です。利用者試験の結果や、Google Cloud / Google AI 接続済みの応募完成版を示すものではありません。架空の依頼を使い、音の好みから品質を採点しないことを一貫して伝えます。

## 開始前

- READMEの手順で起動し、「01 · 依頼は、どちらの相手へ」を選ぶ。
- 初期状態は変更後のコード。中央の「前 → 後を聴く」で、変更前から変更後へ続けて再生する。
- 呼ぶ側と相手の抜粋を表示したまま、音量と出力先を確認する。
- 最初から「不具合の場所を当てて」と依頼しない。この配送変更は両版とも意図どおりの例である。
- ここに書いた台詞を、利用者の感想として報告しない。

全部のサンプルを全曲再生する必要はありません。声のボタンはその関数だけ、接点のボタンはその二者だけを聴きます。再生中に手でコードを読み始めたら追従を解除でき、停止しても接点を保てます。

## 成果として残すもの

配送例なら、例えば「依頼は急ぎの配送対応。呼出先が切り替わり、両方の計画関数は残っている。呼出側が必要なserviceを選べているかを確認した」のように、関係と根拠を残します。実際の試用ではこの文章を復唱させず、本人が指した二者・参照したコード・確認したいことを記録します。

「楽しく聴けた」「もう一度触りたい」と、「関係を説明できた」「確認すべき根拠を指せた」は別に聞きます。3分の案内で説明を理解できたことを、初見で直感的に使えた証拠へ置き換えません。

## テスト記録と実演上の注意

- 予約の保存記録は `base 11/11`、`draft 9/11`、`aligned 11/11`。表示中のパスとソースを含むSHA-256が一致する場合だけ表示する。
- 最初の3シーンは別途Nodeでfixtureを検証しているが、画面の保存記録は未収録。「未実行」という表示を、新しいブラウザテストの失敗と説明しない。
- テスト失敗の中断を追加で試す場合は、その記録に結び付いた専用ボタンを選ぶ。演奏の途中で止まる位置は、実行時刻やクラッシュ行ではない。
- 正常なobject存在確認をエラーにしない。解析できない呼出しを、黙って成功したものにしない。
- 入力コードは実行・外部送信しない。「根拠を見る」と楽評は現在ローカル処理であり、Geminiが調査したとは説明しない。
- 楽評は、コードの書き方・つながり・確認の問いが主役。音名や再生方式の説明で置き換えない。比喩と実装済みの音の範囲を区別し、未表現の差は`soundStatus`の説明をそのまま伝える。
- 音楽だけでは全変更を表せない。書き方や響きの好みを作者の人格・能力・コード品質へ結び付けない。

Google Cloud実行プロダクトとGoogle AIを使う応募条件はまだ未達です。接続後には、その実際の調査過程を示す実演へ更新し、提出リポジトリ・公開版・動画を同じ版へ揃えます。受賞やレビュー効率の改善を保証しません。
